## 2. P0 — Textbook reachable during lessons

### 2.1 Page proportions (`Booklet.tsx`)

`aspect-square` letterboxed a portrait textbook page into a square box, shrinking the
print until a child had to open the zoom modal to read anything. Now `aspect-[3/4]`.

Verified live: box ratio `0.750`, `object-fit: contain`.

### 2.2 The split-screen lesson desk

The booklet previously existed **only** on the unit overview and warm-up screens. A
child mid-conversation could not look back at the story or the instructions at all —
the lesson showed a single per-concept thumbnail inside the chat.

The lesson stage now has a collapsible textbook pane beside the chat: three columns
from `xl` (concepts │ textbook │ chat), stacked below that.

It auto-follows the concept being taught via a new `syncToIndex` prop on `Booklet`
that fires **only when the value changes** — so a child who has manually flipped back
to hunt for a clue keeps their place until the lesson genuinely moves on.

Verified live:

| Action | Active concept | Booklet |
|---|---|---|
| enter lesson | 2.1 | Page 1 of 6 |
| click 2.3 | 2.3 | Page 3 of 6 |
| click 2.5 | 2.5 | Page 5 of 6 |
| **flip back twice by hand** | 2.5 | **Page 3 — holds** |

Unit 1 behaves the same across 22 pages (1.1 → page 2, 1.10 → page 17).

### 2.3 The two-page-table problem (would have made the feature dead for Unit 2)

Textbook pages live in **two different tables** for historical reasons:

- `UploadedPage` — English Unit 1's 22 pages, via the original parent upload flow
- `UnitResource` (`resourceType: "textbook"`) — Unit 2's 6 pages, via admin curation

`getUploadedPageImages` only ever saw the first, so Unit 2 — the newest unit — would
have rendered an **empty pane** with its pages sitting right there.

New `getUnitBookletImages` unions both, filters to `image/*` (UnitResource also holds
PDFs, which `<img>` cannot render), and dedupes by served path.

| Unit | Booklet pages | Concepts resolving for auto-sync |
|---|---|---|
| English 1 | 22 | 13 / 13 |
| English 2 | **6 (was 0)** | 6 / 6 |

### 2.4 The actual "cropped pages" defect

The NotebookLM UX doc blamed `Booklet.tsx`. The real cause was in `AvatarChat.tsx`,
which rendered scanned pages in the illustrations' landscape `aspect-[5/3]` with
**`object-cover`**, slicing the top and bottom off every real page.

Real pages now get a portrait box with `object-contain`; the built-in 300×180 SVG
illustrations keep the landscape box. The in-chat copy is hidden entirely while the
booklet beside it is already showing that same page at full size.

## 3. P0 — Six progression tests loaded

Loaded via `scripts/load-progression-tests.py` (a SQL generator rather than
`seed.ts`, which is the catalog seed and is not run against production — and this
machine has no node toolchain).

**Unit 2 had no test coverage whatsoever before this.** Unit 1 had only a `moderate`
paper explicitly noted as a partial draft covering 1.1–1.3, which was **appended to
rather than overwritten**, so three real hand-authored questions survived.

Every `concept_tested` was hand-mapped to a real live `conceptKey`, and the loader
**aborts the whole transaction** if any fails to resolve — an unmatched key is not a
runtime error, it is silently dropped by the mastery write, so a typo would mean
`ConceptMastery` quietly never updates.

Confirmed idempotent by running it twice. Cached `progression_test` `ContentPack`
rows are dropped so `lib/testPacks.ts` rebuilds them (it caches forever otherwise).

**Verified end-to-end live:** Unit 2's `tough` paper — which did not exist that
morning — builds a clean pack and grades correctly, returning real AI feedback marked
against the authored schemes (2/2 on both questions). Run in **practice mode**, and
confirmed in Postgres that it wrote nothing: newest `TestAttempt` still 2026-08-25,
`ConceptMastery` untouched.

Two judgment calls worth noting:

- A typo in the source JSON was corrected — *"...before whispered the news"* →
  *"before **she** whispered the news."* It is shown verbatim to a 10-year-old in a
  comprehension question.
- The papers are **thin**. That is what the source JSON contains.

## 4. P0 — Horizontal scroll on phones (pre-existing, found while verifying)

The lesson page scrolled sideways at 375px. Confirmed pre-existing (it reproduced
with the new pane hidden), but fixed because the P0 brief explicitly asked for no
overflow. Three real causes, each measured in the live DOM rather than guessed:

1. **Single-column `grid` containers** use an implicit `auto` track sized to
   max-content, so one wide descendant dragged `<main>` itself to 436px inside a
   343px parent. Tailwind's `grid-cols-1` is `repeat(1, minmax(0,1fr))`, which clamps
   the track.
2. **The learn-page header** pinned its two action links `shrink-0` beside an
   unconstrained title block — min-content of 452px.
3. **The chat input** is a flex item with default `min-width:auto`, so it refused to
   shrink below ~184px; the input row's min-content was 402px.

Simulating all three in the live DOM dropped `scrollWidth` from **451 → 375** before
any code was written.

## 5. P1 — Interactive widget engine

Architecture: one `lib/interactiveWidgets.ts` (typed discriminated union + registry
keyed by `Concept.conceptKey`) and one `components/interactive/WidgetDispatcher.tsx`
(dispatch map + all four SVG canvases). Rendered above the chat in the lesson stage;
a concept with no widget authored renders nothing. Inline SVG, Tailwind transitions,
no new dependencies.

A **"Get hint"** button surfaces contextual coaching in an Ezy speech bubble reusing
the real `Avatar` component.

### The four widgets — all verified live, including their failure paths

| Concept | Widget | Verified behaviour |
|---|---|---|
| 1.2 | **The Clue Detective** | Tapping "winked" collapses Jo's eye (`scaleY(1)`→`scaleY(0)`); "grinned" crossfades her mouth to a grin; both clue words lock gold; sparkle fires once both are found |
| 1.9 | **The Sentence Train** | "and" gets a targeted correction; "but" snaps the carriages together (`±28px`) and puffs steam |
| 2.2 | **Poorna's Life Mountain** | Out-of-order tap gets redirected; correct sequence walks the climber up and turns the summit flag gold (`#c99a2e`) |
| 2.6 | **The Prefix Machine** | Wrong prefix triggers the spelling-rule remedial; correct one meshes the gear and advances through "Word 2 of 5" |

### Three deliberate deviations from the brief

**Dispatch is on the spec's own `kind`, not `concept_tested`.** `concept_tested` is
the mastery-mapping key the attempts routes resolve against `Concept.conceptKey`.
Reusing it as a rendering discriminator would couple two unrelated systems and break
the moment two concepts want the same widget, or a concept wants a widget with no
test question pointing at it. Concept → widget is a lookup; what to draw is `kind`.

**Live brand tokens, not the ones quoted.** The spec file's own `theme` block and the
brief both name the **retired** palette (`#1E293B` ink, `#FFFDD0` cream, `#FF6F00`
orange, and a `#FFD700` gold that was never ours). Rendered in the actual live tokens
instead: ink `#16241f`, paper `#f4f6f1`, gold `#9c6f1f` / `#c99a2e`. Character
colours (skin, hair) kept as authored — those are art, not brand.

**Static TS, no Prisma migration.** These specs are authored curriculum that never
varies per student, so they live in git beside the components that render them —
which also honours the brief's own "do not rewrite existing DB schemas" rule.

### Two corrections to the brief's premises

- It described **nine** widgets in `studyezy-p1-interactive-specs.json`; that file
  contains **four**, in much greater depth. The nine shallower ones are the
  `interactiveWidgets` blocks inside `curriculum-english-stage5.json` — **the
  remaining five are unbuilt.**
- It asked to "seed the six missing question papers"; those were already seeded
  earlier the same day, and `studyezy-p1-workbook-tests.json` contains only **Unit
  1**, one question per tier.

### What that file genuinely added

Three questions grounded in the real fable text ("Why Cockerels Crow", Hyena's wife,
the spiky comb), appended via `scripts/load-p1-workbook-tests.py`. **Unit 1 is now
easy 3 / moderate 6 / tough 3**, with `tough` newly covering concept 1.3.

That loader also **normalizes `concept_tested` from `"Concept 1.3"` to `"1.3"`**. As
authored it matched no `Concept` row, and an unmatched key is silently skipped by the
mastery write rather than raising — so every affected attempt would have failed to
update `ConceptMastery` with nothing anywhere to indicate it.

Verified after loading: **all 18 questions across the six English papers resolve to
real concepts, and zero `"Concept "` prefixes survive in the database.**

## 6. Tablet layout bug — introduced this session, then fixed

Screenshotting the new widgets at 820px exposed that **the chat column was collapsing
into the 200px nav column** across the whole 768–1279px band. Between `md` and `xl`
the desk is a two-column grid holding three children, so grid auto-placement wrapped
the chat back into column 1, underneath the nav.

This was introduced by the split-desk change earlier the same day and missed because
that was only verified at 375px (one column) and 1440px (three columns) — the entire
768–1279px band was never looked at.

Fixed with `md:col-start-2` / `xl:col-auto`. Full breakpoint sweep after the fix:

| Viewport | Grid | Nav | Textbook | Chat | H-scroll |
|---|---|---|---|---|---|
| 375 | 1 col | 343 | 343 | 343 | none |
| 768 | `200px 516px` | 200 | 516 | **516** stacked | none |
| 820 | `200px 568px` | 200 | 568 | **568** stacked | none |
| 1024 | `200px 516px` | 200 | 516 | **516** stacked | none |
| 1280 | 3 cols | 200 | 276 | 380 side-by-side | none |
| 1920 | 3 cols | 200 | 276 | 380 side-by-side | none |
